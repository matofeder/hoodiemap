# Sub-project A: Test Mode / Fixture JSON

**Date:** 2026-05-27  
**Status:** Approved

## Problem

Every `GET /api/scene` call hits the Overpass API and takes 3–10 seconds. During UE5 frontend development (Sub-project B), this blocks rapid iteration. Development should work offline and respond instantly.

## Solution

A `?fixture=true` query parameter on `/api/scene` returns a pre-saved JSON file instead of calling `build_scene()`. The fixture is a committed file in the repository — offline, deterministic, and immediately useful as the data contract for UE5 frontend development.

## Scope

This spec covers only the test mode fixture mechanism. The UE5 Pixel Streaming frontend is a separate sub-project.

## Architecture

### New file: `fixtures/pezinok-centrum.json`

Pre-fetched scene response for Pezinok centrum (lat `48.28646434486518`, lon `17.27221245956356`). Generated by running `scripts/capture_fixture.py` and committed to git. Regenerate manually whenever the scene data structure changes.

### Change: `src/api.py`

Extend the `/api/scene` endpoint with an optional `fixture: bool = False` parameter:

```python
@app.get("/api/scene")
async def scene(
    lat: Annotated[float, Query(ge=-90, le=90)],
    lon: Annotated[float, Query(ge=-180, le=180)],
    fixture: bool = False,
):
    if fixture:
        fixture_path = Path(__file__).parent.parent / "fixtures" / "pezinok-centrum.json"
        if not fixture_path.exists():
            raise HTTPException(
                status_code=404,
                detail="Fixture file not found. Run scripts/capture_fixture.py first."
            )
        return json.loads(fixture_path.read_text())
    # existing logic unchanged
    cfg = _get_cfg()
    ...
```

When `fixture=True`, `lat` and `lon` are accepted but ignored. No OSM calls are made.

### New file: `scripts/capture_fixture.py`

Standalone script that calls `build_scene()` with default coordinates and writes the result to `fixtures/pezinok-centrum.json`:

```python
# Usage: python scripts/capture_fixture.py
# Regenerate after scene data structure changes.
```

Reads `config.yaml` for default lat/lon. Creates `fixtures/` directory if it does not exist. Overwrites the existing fixture file.

## Data Flow

```
GET /api/scene?fixture=true
  → api.py reads fixtures/pezinok-centrum.json
  → returns JSON directly (no OSM, no Overpass, no build_scene)

GET /api/scene?lat=48.28&lon=17.27
  → existing live path unchanged
```

## Error Handling

One error case: fixture file missing. Returns `HTTP 404` with message: `"Fixture file not found. Run scripts/capture_fixture.py first."` No other failure modes exist (file is read-only, no network calls).

## Testing

No new unit tests required. Manual verification:

1. `python scripts/capture_fixture.py` → `fixtures/pezinok-centrum.json` created
2. `curl "localhost:8000/api/scene?fixture=true"` → returns JSON scene
3. `curl "localhost:8000/api/scene?fixture=true&lat=0&lon=0"` → returns same JSON (lat/lon ignored)

## Size Estimate

~50 lines of new code across 2 files (`api.py` change + `capture_fixture.py`).
